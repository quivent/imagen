# Artwork factory

KOC-347 builds a local operator service for artwork production. It shares a
durable SQLite queue between built-in image generation handoffs and independent
external-model workers. Existing illustrations are imported as protected
versions, never regenerated by import. This tool makes raster artwork; it does
not author Lithos or deliver 3D worlds.

## Delivery contract

- One persistent request per scene, prompt, model, settings and reference content.
- Atomic worker claims with lease tokens. Expired submission claims require
  reconciliation; they are never automatically submitted again.
- Store remote request IDs immediately; resume polling after interruption.
- Preserve source files and versioned WebP derivatives. Review selects a version;
  generation never replaces the selected version.
- Review and preview locally. Export immutable batches for later integration;
  this service never deploys or overwrites the public atlas.
- Record attempts, durations, supplied costs and review decisions. Unknown cost
  stays unknown. Similarity is a reference suggestion, never a quality judgment.
- Built-in handoff packets contain tool arguments and receipt instructions;
  the daemon does not impersonate or invoke the conversation's built-in tool.

## Start here

The native Mac client is **Artwork Studio**, installed at
`~/Applications/Artwork Studio.app`. It offers a new SwiftUI collection,
inspector, comparison and request interface over this same service. Build and
usage instructions are in [the Mac app guide](../../tools/artwork/macos/README.md).
The browser desk remains available as another client.

The review desk is at **http://127.0.0.1:48620**. It is local to this Mac; it is
not a Vercel deployment or a new visitor-facing page. No API key is needed to
review, queue, import, export, or use the built-in handoff.

Requirements: Python 3.11+ and the `cwebp`/`dwebp` executables already installed
on this machine. No Python or npm packages are installed by this tool.

From the repository root:

```sh
python3 tools/artwork/service_control.py start
python3 tools/artwork/service_control.py status
python3 tools/artwork/service_control.py stop
```

The macOS controller bootstraps a launchd service from a plist inside the local
state directory. It runs outside the agent turn and restarts after a process
exit. It is loaded for the current login; run `start` after a logout/reboot.
Other platforms can run `python3 tools/artwork/artwork.py serve` under their
own service manager. The bind address is deliberately 127.0.0.1.

In the desk, choose **Awaiting your review** to find new candidates. A scene's
version selector keeps previous versions available. Choosing a replacement
checks that the old selection is still the one the page showed; an outdated
page cannot silently replace a newer decision. A selected version cannot be
rejected until another has been selected. “Use as a reference” opens a new
request with an explicit change and preservation prompt.

**Compare versions** opens the selected artwork beside the version under
consideration. Both images open at full size; the comparison stacks on narrow
screens. Escape or **Back to the collection** returns to the invoking button.
The comparison includes the same protected review controls as the cards.
Notes survive filtering, version changes and record refreshes during the open
page; they are not persisted until a review decision is recorded. Reloading or
closing the page discards unsaved notes.

**Prompt and record** distinguishes the stored request from a recorded tool
prompt and shows any documented prompt adjustment. Historical limitations stay
attached. Reference requests read the actual image dimensions. Known subject
families carry forward; imported versions without that metadata ask you to
choose a subject rather than inheriting the previous form's value. The chosen
generator and model remain yours to set in the request form.

## Queue requests

Use the desk or a JSON object/list. `--state PATH` before the command selects
another independent collection; the `ARTWORK_STATE` environment variable also
works. Default data lives in `tools/artwork/.state/`.

```sh
python3 tools/artwork/artwork.py enqueue requests.json
python3 tools/artwork/artwork.py status
```

Example request:

```json
{
  "scene": "scene-151",
  "name": "A quiet coast",
  "brief": "Dark coastal rocks beside a sheltered blue inlet at dawn.",
  "family": "landscape",
  "backend": "builtin",
  "width": 1536,
  "height": 1024,
  "variant": "first"
}
```

Families are `landscape`, `architecture`, `animals`, and `underwater`. The
shared style includes no generic architectural or religious clauses. A `prompt`
field overrides automatic assembly and is preserved as written. `references`
is an array of `{ "path": "/absolute/image.png", "role": "edit-target" }`;
other roles are `reference` and `style`. References are copied and hashed on
enqueue. The browser can only choose images already in the version store.

The cache key includes scene, effective prompt, backend/model, dimensions,
settings, reference contents/roles, and variant. Repeating an identical request
returns its existing job, even after restart. Change `variant` to deliberately
request another image. Display-name changes alone do not bypass this cache.
Imported historical artwork has no reconstructed provider attempt or measured
cost; import does not enqueue anything.

## Built-in execution here

```sh
python3 tools/artwork/artwork.py next --count 6 --worker astra
```

This atomically claims jobs, persists handoffs under `.state/handoffs/`, and
prints compact packets containing the actual `image_gen.imagegen` arguments,
job ID, lease token, and receipt instructions. The tool provides no model
selection; `model` is `builtin`. The only additional setting accepted is
`transparent_background`.

For new images, [builtin_runner.js](../../tools/artwork/builtin_runner.js)
contains the reusable **functions.exec** orchestration: six concurrent calls,
30-second heartbeats, immediate small receipt persistence, then asset processing.
It runs in the agent's tool environment, not Node. Adjust its `repo` constant
for another checkout. It never stores or logs base64 image data. Reference/edit
jobs are handed back to the agent to load the local inputs with `view_image`
before invoking the tool, as the imagegen contract requires. Jay's instruction
to leave output visual judgments to him is preserved.

Manual receipt and heartbeat commands:

```sh
python3 tools/artwork/artwork.py beat JOB TOKEN
python3 tools/artwork/artwork.py complete JOB TOKEN /absolute/generated.png
```

Optional `--receipt-json` records actual tool arguments/timing; optional `--cost`
and `--currency` record a known cost, never an estimate disguised as an invoice.
The source is copied, its dimensions checked, full and 640px WebPs produced,
hashes recorded, and the version marked pending review. Source files may be up
to 50 MB; publication WebPs must each be at most 3,000,000 bytes. A repeated
completion receipt is idempotent only if its token and source hash agree.

## External workers

FLUX is implemented against the official BFL asynchronous API. Supported
endpoints: `flux-2-pro`, `flux-2-max`, `flux-2-klein-4b`, `flux-2-klein-9b`.
Pro/max accept up to eight references; klein accepts four. `settings` supports
`seed`; pro/max additionally support `disable_pup`. API credentials are read
from the worker environment and are never passed to the browser or image URLs.

Set `BFL_API_KEY` privately in the worker environment, then:

```sh
python3 tools/artwork/artwork.py worker --backend bfl --concurrency 6
```

The desk and worker are separate processes. Queueing alone never starts a paid
worker. Ctrl-C/SIGTERM stops acquisition and lets bounded in-flight operations
settle. New 429 responses are retried with backoff, up to three attempts. Other
definite rejections stop. Timeout/5xx ambiguity holds the request as uncertain.
Once a remote ID is persisted, polling resumes that same ID after restart.
Provider-returned costs are recorded as **BFL credits**, not dollars.

Other APIs and self-hosted generators use the command adapter:

```sh
python3 tools/artwork/artwork.py worker --backend command --argv model-command.json --concurrency 1
```

`model-command.json` is an argument array such as
`["/absolute/model-venv/bin/python", "/absolute/model-worker.py"]`. No shell
evaluation is used. The process receives one JSON document on stdin:

```json
{"job":"…","attempt":"…","spec":{"prompt":"…","model":"…"},"outputDirectory":"/assigned/path"}
```

It must write the image inside `outputDirectory` and emit one JSON receipt on
stdout: `{ "source": "/assigned/path/result.png", "cost": 0.02, "currency": "USD" }`.
Cost fields are optional. All dimensions, settings and references are in `spec`.
The process has a 15-minute timeout; interruption/nonzero exit is uncertain,
not automatically retried. No specific local model weights are bundled. The
worker adapter is the extension point for Gemini, diffusion pipelines, or the
approved OpenAI CLI; it is not a claim that those backends were connected here.

Official contract references, checked 2026-10-17:
[FLUX.2 pro request](https://docs.bfl.ml/api-reference/models/generate-or-edit-an-image-with-flux2-[pro].md),
[result polling](https://docs.bfl.ml/api-reference/utility/get-result.md),
[BFL OpenAPI schema](https://api.bfl.ai/openapi.json).

## Recovery and safe retries

The queue uses SQLite WAL, full synchronous writes, and atomic transactions.
Active claims expire after ten minutes. Built-in and command submissions with
expired leases become uncertain, never automatically queued. Submitted remote
jobs can be reclaimed for polling; the lease token rotates and fences the old
worker. There is no claim of exactly-once remote execution: a provider accepting
a POST immediately before a process crash is inherently ambiguous without
provider-side idempotency. We hold that case for evidence.

- Known local output: use its persisted handoff token with `complete`.
- Known remote ID: `artwork.py remote JOB TOKEN REQUEST_ID` resumes polling.
- Confirmed safe to submit again: `artwork.py retry JOB --reason "evidence"`.
- Unclaimed work no longer wanted: `artwork.py cancel JOB --reason "reason"`.

Handoffs and small result receipts remain in `.state/handoffs/`; command receipts
and remote downloads remain in `.state/work/`. Partial conversions may remain
as unreferenced directories. They are deliberately retained for reconciliation;
there is no automatic cleanup that could erase a recovered result.

## Review, similarity, export and backup

```sh
python3 tools/artwork/artwork.py review VERSION accepted --note "Chosen after review"
python3 tools/artwork/artwork.py review NEW accepted --replace OLD --note "Prefer the new light"
python3 tools/artwork/artwork.py similar VERSION
python3 tools/artwork/artwork.py export review-batch --pending
python3 tools/artwork/artwork.py export selected-batch
python3 tools/artwork/artwork.py backup recovery-copy
```

Similarity uses exact SHA-256 and a 64-bit perceptual difference hash. It ranks
broad composition/light patterns. It is not semantic embedding search, animal
anatomy detection, geographic verification, or an acceptance rule. Reference
editing implements the useful “change this part” workflow; no pixel-delta
storage or inference-speed saving is claimed.

Exports are new folders under `.state/exports/` with verified assets and an
ordered manifest. Existing export names cannot be overwritten. Pending exports
are explicitly previews. These are staging artifacts: integration, a public
preview deployment, and production promotion remain separate release actions.

Backups include a consistent SQLite snapshot, versioned images, references,
handoffs, and available work receipts under `.state/backups/NAME`. A successful
backup has `backup.json` with `complete: true`; incomplete directories are not
recovery copies. For recovery, stop desk and workers, preserve the current state
directory, and restore the backup to its recorded `restoreRoot`, then start the
desk. Paths are absolute: moving a collection to a different root is not yet a
supported restore. Copy a verified backup to another disk for protection from
disk failure; the built-in local copy is not an off-device backup.

**The state folder contains original artwork and review records. It is durable
user data, not a disposable build cache.** Git ignores it; source commits do not
back it up. Existing public artwork stays tracked in its original paths.

Metrics distinguish unknown costs from zero, keep different currencies/credits
separate, and report attempts and summed attempt time per accepted generated
version, including a breakdown by backend/model. Historical imported selections
do not inflate the new-generation acceptance denominator. Summed attempt time
includes handoff/processing and is not concurrent wall-clock throughput; raw
built-in generation time is in the receipt when measured. No new performance
improvement percentage is asserted from the single proof image.

## Verification and boundaries

```sh
python3 -m unittest discover -s tools/artwork/tests -v
node --check tools/artwork/desk.js
node --input-type=module --check < tools/artwork/builtin_runner.js
node scripts/voice-lint.mjs
```

The tests cover competing workers, duplicate requests, stale claim fencing,
restart recovery, ambiguous submissions, rate limits, a real command subprocess,
simulated BFL polling, receipt conflicts, dimensions, selected-version protection,
tampered exports, similarity, imports, backups and HTTP host/origin/token checks.

The desk uses native labeled controls, visible focus, a skip link, 56px controls,
no animation or refresh timer, and one polite status region. Recorded contrast:
primary text/background 14.64:1; secondary text/background 10.55:1; control text
11.64:1; link/focus colour 11.03:1; control borders 4.39:1. These are calculated
colour ratios and source checks, not a claim of completed browser/screen-reader
testing. No visual review was performed, following Jay's instruction.

C1–C13 review: this is a local operator surface, isolated from visitor routes,
auth, saved places, 3D worlds and presence. It adds no visitor tracking, network
dependency, motion, score, clinical language or destructive content operation.
Operator production counts are not measurements of a person using Kinship.
No product/server files or Lithos were edited; site/server release gates do not
apply to this isolated Python service. Its actual HTTP routes were boot-tested.

Live evidence and remaining limitations are recorded in
[the tracker receipt](../../.tracker/notes/artwork-factory.md).

## Private two-GPU FLUX comparison

The factory can now route command jobs to private, resident FLUX.1 dev and
FLUX.2 dev workers. FLUX.2 keeps BF16 image weights and uses the prequantized
NF4 Mistral encoder. The adapter carries requests over SSH and verifies each
returned original against its generation receipt; results enter the existing
collection as pending versions. See [the worker guide](../../tools/artwork/remote/README.md)
for setup, model revisions, recovery and the connection to Jay's existing FLUX
studio and R2 publisher. Runtime evidence is in
[the setup note](../../.tracker/notes/artwork-flux-workers.md).
