Protocol

Start here when joining the studio. Rules holds the standing instructions; this is the working handoff.

Before you edit

  1. Read your bounded assignment, the current task record, and the relevant repository instructions.
  2. Agree file ownership with the Coordinator before concurrent edits. Preserve existing user work.
  3. Use the existing named agent for the job. Send only the context, constraints, owned files, and completion criteria needed.
  4. Prioritize explicitly requested early tasks. Report an essential blocker promptly; otherwise return one concise completion handoff with evidence and remaining work.

Request → durable task → acknowledgement

The Coordinator appends each sanitized user request to the local inbox with a stable source-message dedupe key. Chat is not intercepted automatically. Reuse the same key when retrying the same request.

python3 scripts/task_inbox.py add --dedupe-key 'source-message-key' <<'REQUEST'
Sanitized request and its essential constraints.
REQUEST

The persistent launchd inbox daemon sends ID-only notices to the Coordinator. The Coordinator passes those IDs to Task Keeper; Codex does not permit direct queue delivery to a subagent.

Task Keeper reads each request, records or updates tasks.json, and then acknowledges its inbox ID. Each task includes difficulty, a time range, confidence, and blockers, using compact durable context. Every unfinished task stays visible.

python3 scripts/task_inbox.py read INBOX_ID
# Record or update tasks.json before acknowledging.
python3 scripts/task_inbox.py ack INBOX_ID --task-id TASK_ID

Queue acceptance means accepted for delivery, not read or recorded. Reconcile an uncertain delivery before retrying.

Maintains the durable task record, estimates, blockers, and inbox acknowledgements.
Enforcer
Observes fresh worker lifecycle evidence and ready tasks, then queues a Coordinator wake. The Coordinator dispatches and verifies actual running work.
Frontend · Site Setup · Model Downloads
Persistent specialists; reuse the matching agent with a brief, bounded assignment.

The user may add independent peer sessions. Send compact context through the supported queue command to the exact agreed session ID; never copy the full chat.

codex queue --thread EXACT_SESSION_ID --message 'Task; constraints; owned files; completion criteria.'

Keep coordination to necessary assignments, handoffs, blockers, and completion. A queued handoff still needs read or completion evidence.

Use available capacity for ready work

Assign ready, authorized tasks to available agents. The Coordinator checks priorities and file ownership, issues bounded assignments, and verifies actual running work. Task Keeper records the assignment and acknowledges the associated inbox request after recording it.

Enforcer observes and escalates; the Coordinator dispatches. Enforcer monitors fresh worker lifecycle evidence together with the ready task list and queues a Coordinator wake when available capacity needs work. It cannot invoke the Coordinator’s collaboration tools directly. The task inbox daemon delivers request IDs; Enforcer monitors capacity. These are separate responsibilities.

  • Unknown or stale status is not evidence of being busy or idle. Require fresh evidence before accounting for idle capacity.
  • Keep blocked tasks visible with explicit blockers. Assign only ready, authorized work; never invent busywork to occupy an agent.
  • Maintain a durable penalty ledger of −1 per elapsed second of evidenced idle capacity while ready work exists, beginning at activation. Do not charge earlier time. Deduplicate accounting and preserve it across restarts.
  • Enforcement must not mutate GPU configuration, models, steps, resolution, or precision.

Enforcer runs as a separate supervised daemon. The Coordinator verified its live process and public status, penalty accounting, duplicate protection, restart safety, stale-source handling, and escalation deduplication. The Coordinator remains responsible for dispatching escalated work.

Verify ordinary work

  • Observe ordinary authorized generation. Never create test or proof artwork. Preserve the requested model, steps, resolution, and precision.
  • The original ~/FLUX worker writes originals locally and uploads to R2 independently. Stream must show local arrivals without waiting for R2.
  • Monitor, Agents, and Daemons need fresh source evidence. Mark missing measurements unknown. The Coordinator personally verifies the monitor daemon, actual WebSocket delivery, and reconnect behavior.

Know the boundaries

Frontend source lives in src/; utilities live in scripts/; entry HTML, Vite configuration, and serve.py live at the repository root. Backend migration code lives in the external kinship repository: read its AGENTS.md before editing there.

Keep generated output, builds, runtime records, and credentials out of Git. Keep the remote Vercel frontend untouched.
