Rules

Standing instructions for this studio and the current session.

  1. Record every task

    Pass each requested task to Task Keeper so it appears on the task list.

  2. Start small tasks promptly

    The coordinator may take small or early tasks immediately while keeping the task record current.

  3. Reuse the named agents

    Keep persistent agents with readable names. Give them concise context when assigning or handing off work.

  4. Assign ready work to available agents

    The Coordinator must assign ready, authorized tasks to available agents and verify that work actually starts. Unknown or stale status does not mean busy. Show blocked work and its blockers explicitly; never invent busywork.

  5. Enforce available capacity with evidence

    Enforcer observes fresh worker lifecycle evidence and the ready task list, then escalates to the Coordinator for dispatch. Its durable penalty is −1 per elapsed second of evidenced idle capacity while ready work exists, counted from activation without retroactive charges. Accounting must survive restarts without duplicate charges. Enforcement must not change GPU configuration or generation settings. The Coordinator must verify the actual daemon before reporting it live.

  6. Keep the repository clean

    Exclude generated artifacts, dependencies, stale files, and local runtime records from commits.

  7. Leave the Vercel deployment alone

    Keep the existing remote Vercel deployment untouched unless a change is explicitly requested.

  8. Verify the live monitor

    The coordinator must personally verify the monitor daemon and real WebSocket evidence before reporting live monitoring as working.

  9. Preserve generation settings

    Keep the requested settings in model comparisons. Do not reduce precision or steps without being asked.
